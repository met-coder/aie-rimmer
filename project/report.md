## 2. Постановка задачи и контекст

1. **Предметная область и задача:**
   - задача: классификация изображений одежды из 10 категорий (T-shirt/top, Trouser, Pullover, Dress, Coat, Sandal, Shirt, Sneaker, Bag, Ankle boot).
   - пользователь: разработчик или качественный инженер, который хочет проверить классификацию одежды через API-сервис.

2. **Формулировка задачи в терминах ML/ИИ:**
   - входные данные: чёрно-белые изображения размера 28×28 пикселей;
   - целевая переменная: один из 10 классов одежды;
   - требования: простой, воспроизводимый сервис, скорость инференса и понятная метрика качества.

3. **Целевые метрики качества:**
   - основная метрика: accuracy;
   - метрика выбрана потому, что задача классификации многоклассовая и корректность предсказания является ключевым критерием.

---

## 3. Данные

1. **Источник данных:**
   - открытый датасет Fashion-MNIST от Zalando Research;
   - данные автоматически скачиваются при запуске через torchvision.datasets.FashionMNIST.

2. **Структура данных:**
   - массив изображений 28×28 и метки от 0 до 9;
   - данные являются изображениями одежды, тип данных — изображения/числовые пиксели.

3. **Предобработка и EDA:**
   - предобработка: нормализация в диапазоне [-1, 1], resize не требуется для исходных 28×28, преобразование в тензор;
   - EDA: визуализация примеров классов, распределение классов и статистика пикселей;
   - наблюдения: классы сбалансированы, выборка не содержит пропусков, отличия между некоторыми визуально похожими классами (например, Shirt vs Pullover).

Основные шаги EDA находятся в notebooks/01_eda_baseline.ipynb и notebooks/02_model_comparison.ipynb.

---

## 4. Модели и подходы

1. **Базовые (baseline) модели:**
   - baseline: LogisticRegression на сплюснутых пикселях 28×28;
   - результат: accuracy = 0.8339 на тестовой выборке.

2. **Улучшенные модели и эксперименты:**
   - улучшенная модель: простая CNN-архитектура с двумя сверточными слоями, max-pooling и двумя полносвязными слоями;
   - важные параметры: размер батча 128, lr=1e-3, optimizer=Adam, 3 эпохи;
   - эксперименты: сравнение baseline и CNN, визуализация кривых обучения и confusion matrix.

3. **Нейросетевые модели:**
   - архитектура: Conv2d(1,16) -> ReLU -> MaxPool2d -> Conv2d(16,32) -> ReLU -> MaxPool2d -> Flatten -> Linear(64) -> ReLU -> Linear(10);
   - особенности обучения: простой цикл обучения, загрузка данных через torchvision, выполнение на CPU.

Эксперименты описаны в notebooks/02_model_comparison.ipynb.

## 5. Экспериментальный протокол и результаты

1. **Экспериментальный протокол:**
   - выборка: train/test, стандартный split Fashion-MNIST (60000/10000);
   - метрики: accuracy на тестовой выборке;
   - для baseline и CNN использовался один и тот же тестовый набор.

2. **Сравнение моделей по метрикам:**

| Модель / конфигурация | Описание | Accuracy | Комментарий |
|-----------------------|----------|----------|-------------|
| LogisticRegression | Baseline на сплюснутых 28×28 пикселях | 0.8339 | Быстрый baseline без сверточных слоёв |
| SimpleCNN | CNN с двумя сверточными слоями | 0.8842 | Итоговая модель, лучше по accuracy |

3. **Выбор финальной модели:**
   - финальная модель: SimpleCNN;
   - причина: лучшая accuracy при сохранении простоты архитектуры и адекватной скорости обучения;
   - trade-off: модель сложнее baseline, но остаётся лёгкой для CPU-инференса и понятной для объяснения.

## 6. Архитектура решения и сервис

1. **Архитектура пайплайна:**
   - предобработка: преобразование изображения в тензор, нормализация;
   - модель: src/train.py и src/models/predict.py;
   - сервис: src/service.py, который загружает модель и принимает файлы через /predict.

2. **API и endpoints:**
   - GET /health — возвращает { "status": "ok" };
   - POST /predict — принимает изображение и возвращает предсказанный класс и уверенность;
   - GET /metrics — счётчик запросов и средняя задержка.

3. **Технологический стек:**
   - Python, FastAPI, PyTorch, torchvision, scikit-learn;
   - Docker: есть Dockerfile, сборка и запуск описаны в README.md.
