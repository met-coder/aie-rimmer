Краткое описание (2-4 предложения): Проект решает задачу многоклассовой классификации изображений одежды из 10 категорий. Используется открытый датасет Fashion-MNIST, сравнение бейслайна на логистической регрессии и простой свёрточной нейросети (CNN). 2. Структура проекта
Проект организован в следующей структуре:
- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки: EDA, прототипы моделей, отдельные эксперименты.
  - `01_eda_baseline.ipynb` – разведочный анализ и baseline.
- `src/` – основной код проекта: модули для работы с данными, обучение моделей, запуск сервиса и скриптов.
  - `data/`
    - `preprocess.py` – предобработка изображений.
  - `models/`
    - `predict.py` – архитектура, загрузка весов, инференс.
  - `service.py` – FastAPI-сервис, эндпоинты `/health` и `/predict`.
  - `train.py` – модуль обучения модели.
- `data/` – демонстрационные/учебные данные: только открытые, синтетические или обезличенные данные; при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы (`config.yaml`, `.env.example`).
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты и результаты экспериментов (`model.pt`, `metrics.json`).

3. Требования и быстрый запуск

Требования:

- Python >= 3.10
- Docker (опционально для контейнеризации)

Быстрый старт — команды для Windows PowerShell (копировать/вставить):

```powershell
cd "c:\Users\Matthew\Desktop\цифровая кафедра\aie-rimmer\project"
python -m venv .venv
.\.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
# Обучить модель и сохранить в artifacts/
python -m src.train
# Запустить сервис
uvicorn src.service:app --host 0.0.0.0 --port 8000
```

Docker:

```powershell
docker build -t fashion-cls .
docker run -p 8000:8000 fashion-cls
```

Переменные окружения (опционально):

- `MODEL_PATH` — путь к файлу модели (по умолчанию `artifacts/model.pt`)
- `PORT` — порт сервиса
- `LOG_LEVEL` — уровень логирования
- `DEVICE` — `cpu` или `cuda` (если доступна)

Тестирование:


8. Ограничения и дальнейшая работа
Текущие ограничения:
- Низкое разрешение входных изображений (28×28), что ограничивает применимость в реальных e-commerce сценариях.
- Отсутствует валидация формата/размера файла на уровне API.
- Фиксированная архитектура без выбора модели через конфиг.

Направления развития:
- Добавление аугментаций данных и fine-tuning предобученных моделей (ResNet18, EfficientNet).
- Внедрение rate-limiting, аутентификации и Prometheus-метрик.
- Пакетный инференс (`POST /batch_predict`) и CI/CD пайплайн.
