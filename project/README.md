Краткое описание (2-4 предложения): Проект решает задачу многоклассовой классификации изображений одежды из 10 категорий. Используется открытый датасет Fashion-MNIST, сравнение бейслайна на логистической регрессии и простой свёрточной нейросети (CNN). Результат — FastAPI-сервис с эндпоинтами `/health` и `/predict`, упакованный в Docker для лёгкого воспроизведения.

2. Структура проекта
Проект организован в следующей структуре:
- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки: EDA, прототипы моделей, отдельные эксперименты.
  - `01_eda_baseline.ipynb` – разведочный анализ и baseline.
- `src/` – основной код проекта: модули для работы с данными, обучение моделей, запуск сервиса и скриптов.
  - `data/`
    - `preprocess.py` – предобработка изображений.
  - `models/`
    - `predict.py` – архитектура, загрузка весов, инференс.
  - `service.py` – FastAPI-сервис, эндпоинты `/health` и `/predict`.
  - `train.py` – модуль обучения модели.
- `data/` – демонстрационные/учебные данные: только открытые, синтетические или обезличенные данные; при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы (`config.yaml`, `.env.example`).
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты и результаты экспериментов (`model.pt`, `metrics.json`).

4. Как запустить проект
4.1. Запуск обучения модели

Windows (PowerShell / CMD):
.venv\Scripts\activate
python src\train.py

Linux / macOS:
source .venv/bin/activate
python src/train.py

После успешного выполнения модель сохраняется в `artifacts/model.pt` (путь относительно корня проекта). 

Дополнительно в `artifacts/metrics.json` хранится результат сравнения baseline и итоговой модели по accuracy.

4.2. Запуск сервиса (API/веб-интерфейс)
Вариант 1: Без Docker (локально)
cd project
source .venv/bin/activate
uvicorn src.service:app --host 0.0.0.0 --port 8000

Или, если используется Docker:
cd project
docker build -t fashion-cls .
docker run -p 8000:8000 fashion-cls

Опишите:
- Сервис поднимается на порту `8000`.
- Эндпоинты: `GET /health` (проверка статуса), `POST /predict` (приём изображения, возврат класса и уверенности).
- Эндпоинты: `GET /health` (проверка статуса), `POST /predict` (приём изображения, возврат класса и уверенности).
- Дополнительно: `GET /metrics` — простая внутренняя метрика запросов (count, avg_latency_ms).
- Тестирование: открыть `http://localhost:8000/docs` и отправить запрос через Swagger UI, либо `curl -X POST http://localhost:8000/predict -F "file=@path/to/image.png"`.

Советы по запуску и окружению:

- Переменные окружения, которые поддерживаются:
  - `PORT` — порт (по умолчанию `8000`)
  - `LOG_LEVEL` — уровень логирования (`DEBUG`, `INFO`, `WARNING`, `ERROR`)
  - `MODEL_PATH` — путь к файлу модели (относительный или абсолютный). По умолчанию указан в `configs/config.yaml`.

Пример запуска через Docker (порт и лог уровень можно задать через env):

```bash
docker build -t fashion-cls .
docker run -p 8000:8000 -e PORT=8000 -e LOG_LEVEL=INFO fashion-cls
```

Запуск тестов (локально в виртуальном окружении):

```bash
cd project

pip install -r requirements.txt
pytest -q
```

8. Ограничения и дальнейшая работа
Текущие ограничения:
- Низкое разрешение входных изображений (28×28), что ограничивает применимость в реальных e-commerce сценариях.
- Отсутствует валидация формата/размера файла на уровне API.
- Фиксированная архитектура без выбора модели через конфиг.

Направления развития:
- Добавление аугментаций данных и fine-tuning предобученных моделей (ResNet18, EfficientNet).
- Внедрение rate-limiting, аутентификации и Prometheus-метрик.
- Пакетный инференс (`POST /batch_predict`) и CI/CD пайплайн.
